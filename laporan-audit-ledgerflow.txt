1.2 ✅ Sudah diterapkan dengan baik
--------------------------------------------------------------------------------
1. Jurnal POST (journal.ts:106-375) — validasi terlengkap di repo:
   - Minimal 2 baris; setiap baris wajib accountCode
   - Nominal >= 0 dan maksimal 2 angka desimal
   - Tepat satu sisi debit ATAU kredit per baris (tidak boleh keduanya/kosong)
   - Periode wajib ada dan berstatus "open"
   - entry_date harus berada dalam bulan periode yang dipilih
   - Total debit = total kredit (toleransi 0.01)
   - Semua akun harus ada & aktif di company yang sama
   - Double-entry via RPC atomik create_journal_entry + fallback non-atomik
     yang ber-rollback (hapus entry jika insert line gagal)

2. WhatsApp OTP (wa-auth.ts):
   - OTP di-hash SHA-256 (baris 58-61), bukan disimpan teks
   - Perbandingan memakai timingSafeEqual (anti timing attack)
   - Expiry 5 menit; maksimal 5 percobaan salah lalu kunci
   - Cooldown kirim ulang 60 detik; rate-limit per-IP in-memory (baris 34-50)
   - Anti-loncatan: nomor dicek belum terdaftar sebelum konsumsi OTP
   - Rollback provisi akun bila gagal di tengah (tidak ada data yatim)

3. Webhook Midtrans (payments.ts:647-900):
   - Verifikasi signature SHA-512 (baris 668-684) — tolak webhook palsu
   - Rekonsiliasi nominal sebelum aktivasi subscription (baris 774-793)
   - Idempotensi & anti out-of-order (baris 756-772)
   - Mapping status lengkap (capture/settlement/cancel/deny/expire/refund)

4. Otorisasi:
   - requireRole middleware (middleware/auth.ts:47-62) dipakai konsisten
     di semua endpoint sensitif
   - Tenant isolation: company_id SELALU dari JWT, bukan body/query
   - IDOR guard: companies.ts:20-23, users.ts:29-32, ledger.ts:71-75,
     payments/test-complete:500-503, upload/proof:34-44

5. Upload (lib/storage.ts):
   - Allowlist MIME (PNG/JPG/WebP/GIF), batas 5 MB, cek file kosong
   - sanitizeFolder anti path-traversal

6. Password reset (password-reset.ts:47-97):
   - Target user WAJIB diturunkan dari token, bukan email body (baris 82-89)
     -> anti account-takeover
   - Email body harus cocok dengan pemilik token; pesan error generik
   - Token sekali pakai (used flag) + expiry 1 jam

--------------------------------------------------------------------------------
3.1 Definisi role
--------------------------------------------------------------------------------
- BUKAN enum PostgreSQL, melainkan TEXT + CHECK constraint:
    role TEXT NOT NULL CHECK (role IN ('admin','akuntan','owner'))
  - database/database.sql:39 (tabel users)
  - database/database.sql:350 (tabel company_members)
- Direplikasi di 3 tempat kode:
  - ALLOWED_ROLES (user-management.ts:11)
  - tipe JWTPayload.role (lib/jwt.ts:10-16)
  - hardcode string di requireRole(...) di setiap route
- Model data:
  - users memiliki company_id NOT NULL (satu company per user secara praktis)
  - tabel company_members (M:M, database.sql:345-356) dipakai paralel
  - ⚠️ Latent bug: company_members.role DEFAULT 'member' (baris 350) MELANGGAR
    CHECK constraint sendiri (default 'member' tidak ada di list). Insert
    tanpa role akan gagal; tidak terpicu karena kode selalu menyetel role.
- RLS dimatikan (database.sql:223-225); semua otorisasi di level aplikasi.

5. FITUR BARU: ADMIN GATE (dashboard admin khusus)
================================================================================
Implementasi sesuai spesifikasi (password-only, terpisah total dari alur
login WhatsApp OTP user biasa).

BACKEND:
- backend/src/routes/admin-gate.ts
  - POST /api/admin-gate/verify: { password } -> bcrypt.compare terhadap
    env ADMIN_GATE_PASSWORD_HASH. Sukses -> JWT terpisah { type:
    "admin-gate" } TTL 6 jam (lib/adminGateJwt.ts). Gagal -> 401 generik.
  - Rate limit KETAT (in-memory per IP): maks 5 percobaan gagal/15 menit,
    lalu blokir 1 jam (pola dari wa-auth.ts, diperketat).
  - Audit log WAJIB tiap percobaan (success/failed/blocked): timestamp, IP,
    status -> tabel admin_gate_logs; bila migrasi belum jalan, fallback ke
    log server (console) yang persisten.
  - GET /api/admin-gate/logs: riwayat untuk dashboard admin, dilindungi
    middleware requireAdminGate.
- backend/src/middleware/admin-gate.ts: verifyAdminGateToken — HANYA menerima
  token type "admin-gate"; token user biasa ditolak (401).

SETUP MANUAL (developer, sekali saja):
1. Generate hash bcrypt:  node -e "console.log(require('bcryptjs').hashSync('PASSWORD_PILIHAN_KAMU', 10))"
   (dari folder backend; hash bcryptjs kompatibel dengan bcrypt).
2. Set di backend/.env:  ADMIN_GATE_PASSWORD_HASH=<hasil hash>
   JANGAN commit .env (sudah ada di .gitignore).
3. Jalankan database/migration-admin-gate.sql di Supabase SQL editor
   (agar audit log tersimpan ke tabel, bukan hanya log server).
